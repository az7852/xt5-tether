# 使用指南

[返回项目首页](../README.md)

为 FUJIFILM X‑T5 开发的原生 Android 应用：用相机快门拍照，手机自动接收并显示照片。支持 USB Host / PTP，以及同一局域网的富士无线联机协议，不依赖电脑中转。

**当前状态：0.9.2 测试版。84 项协议、网络、保存、图片几何、预览队列、图库选择与拍摄参数格式测试通过。USB 收图已由用户在 X‑T5 上确认可用；Wi‑Fi 已在真实手机与 X‑T5 固件 4.31 上成功连接、接收并显示两张 JPEG。**

## 照片保存位置

顶部 **⋮ → 设置 → 照片保存位置**，选择并点「保存」：

- **App 图库**（默认）：原图保存在应用目录，不自动进入系统相册；可随时手动「导出」。卸载 App 会删除应用内原图。
- **本地相册**：JPEG 自动保存到系统相册 `Pictures/XT5Tether`；RAF 原图保存到 `Download/XT5Tether`，App 继续显示 RAF 内嵌 JPEG。原图仍可在 App 中查看，正常完成后清理传输临时副本；卸载 App 不会删除这些公共文件。

用户已确认设置正常，并能在 App 和系统相册中看到照片。选择会记住，影响之后保存的照片；已有照片不自动搬动。App 图库合并展示本应用私有原图与本应用自动保存到相册的原图，不读取用户其他相簿。重复导出同一原图会复用已保存文件。

保存到相册使用 Android MediaStore，不申请读取整机相册的权限。完整写入、长度核验、同步落盘并发布成功后，才释放相机临时对象；如果相册保存失败，完整原图保留在 App 图库，停止联机并报告错误。

## 拍摄参数显示

**⋮ → 设置 → 查看与显示 → 显示拍摄参数 → 保存**，默认关闭，保存后立即生效并记住选择。

- 开启时在普通预览与全屏底部显示两行参数：光圈、快门、ISO、焦距，以及曝光补偿、测光模式、曝光程序、35 mm 等效焦距。
- 点参数栏打开完整信息，另有机型、镜头、拍摄时间、白平衡、曝光模式、闪光灯、光源、色彩空间和厂商，共 17 个 EXIF 字段。
- 从当前照片的 EXIF 读取，不发送额外相机请求；复用原本读取方向信息时的解析结果，切换开关无需重读原图。RAF 使用内嵌 JPEG 记录的参数；缺失、不合法或尚未保存的字段显示「—」，不沿用上一张的值，不推算白平衡色温、胶片模拟等 MakerNote 信息。
- 参数采用照片区域内的叠层，不改变照片工作区大小。关闭后普通预览仅显示基础文件信息，全屏保持简洁。

## 图库多选与删除

在右侧（手机窄屏为底部）长按一张已保存缩略图，直接选中并进入多选，不弹出菜单。随后点其他缩略图勾选；缩略图角标显示选择状态，工具栏显示张数，支持全选、清空、取消、批量导出和批量删除。预览大图与全屏不再叠放删除按钮。

导出保持完整私有原图，将 JPEG 保存到系统相册、RAF 保存到下载/XT5Tether；重复导出复用已有副本。导出和删除在后台顺序处理并显示数量进度，失败项保留选择供重试。多选期间暂停跟随，取消或操作成功后恢复之前的跟随状态；新拍照片不会自动选中，滚出最近 30 张的已选原图仍保留在本批对象中。

打开「图库」，点右上角「多选」或长按一张已保存照片，点按照片勾选，再点底部「删除」。支持全选、取消全选和取消选择；手机和平板使用同一套固定高度的顶栏、底栏，选择状态变化不挤动网格。

- 删除前确认张数和范围。确认后永久删除所选照片的 App 私有原图及本 App 保存到系统相册／下载目录的同名副本，无法撤销，不移动到系统回收站；相机存储卡不受影响。
- 待下载／正在保存的队列条目不能选择或删除。选择期间新收到的照片不会自动勾选；确认弹窗出现后的新照片也不会加入本次删除。
- 删除在后台顺序执行，显示处理进度，完成后同步更新图库、侧栏和当前预览。单张失败不阻止其他已选照片，未完成条目保留并报告原因。
- 只允许操作 App Captures 目录中的完整照片，以及归属本应用、位于 XT5Tether 目录的已发布 MediaStore 照片。不读取或删除其他应用的相册、未完成临时文件，也不发送相机删除命令。

## 看图界面与平板布局

- 深色背景、低饱和浅绿强调色、圆角照片区与侧栏卡片，按钮与信息层使用统一间距；右上角全屏和更多按钮各保留 48 dp 点击区域，按钮之间留 8 dp 间隔。
- 固定高度顶栏同时展示连接状态与单行提示；重连、错误和传输消息只更新内容，不再插入额外状态行。点按提示查看完整详情。
- 手机竖屏使用底部胶片条；宽屏使用右侧双列照片栏。队列数量、速度、进度与暂停按钮始终占用固定空间，连接状态和队列变化不会挤动照片；文件信息放入预览底部叠层。
- 轻触照片或点右上角全屏按钮，隐藏工具栏、照片信息和缩略图；点右上角退出按钮或返回键恢复。双击缩放与双指缩放仍保留。
- 宽屏平板和手机横屏使用大预览加右侧双列照片栏；窄窗口回到底部胶片条。根据当前窗口宽度切换，因此适配旋转、分屏与自由窗口。
- 「图库」改为自动计算列数的缩略图网格，展示文件名、时间、大小；点选照片回到预览并暂停跟随，点「跟随」恢复接收新照片时自动显示。
- 旋转和窗口布局切换复用同一个照片视图，保留选中的照片与缩放位置；缩略图缓存最多约 12 MiB。
- 正式预览按当前照片区域的实际像素自动匹配清晰度：依据当前窗口尺寸、横竖屏、全屏状态与缩放倍率重算，不使用固定的 2560 长边限制，也不按 dp 当像素。双击在触点处查看原像素细节，拖动后补读对应位置。图片信息显示实际 JPEG 分辨率。
- 即使解码采样级别不变，窗口尺寸变化也会生成相应尺寸的预览。大图分段读取、缩放到显示尺寸，保留细节同时限制中间位图内存。

USB 的 JPEG 直接开始传输，从文件开头的元数据中提取完整预览，跳过传输前单独获取缩略图的相机事务；无线连拍优先使用独立预览，见下文队列策略。先显示取景结果，原图继续完整接收并保存。实拍样本的 FlashPix 预览为 640×480，在接收到前 114,688 字节时已可提取；这是过渡预览，稍后自动换成清晰原图。原图传输耗时仍受文件大小、相机 Wi‑Fi 和网络状况影响。没有嵌入预览或元数据过大时等待完整文件。

手机与小米 Pad 横竖屏已通过真机显示检查，Pad 另已通过 Wi-Fi 实拍收图。各分屏尺寸仍待逐项验证。没有使用安卓模拟器。

## Wi‑Fi 连接

1. 拔下相机 USB 线。让手机和 X‑T5 连接同一路由器的 Wi‑Fi。
2. 相机 → 网络/USB 设置 → 网络设置 → 无线接入点设置，选路由器并完成连接。
3. 相机连接模式选择 **无线联机拍摄固定 / WIRELESS TETHER SHOOTING FIXED**。
4. App 顶部点 **连接 → Wi‑Fi 自动发现**。也可以在相机网络设置中查看 IP，选择 **连接 → Wi‑Fi 输入相机 IP**。
5. 等待顶部显示绿色 `Wi‑Fi`，如机身有访问确认请按 MENU/OK。先以 JPEG FINE 拍一张验证自动接收。

这里使用无线联机模式，不需要蓝牙配对，也不使用 XApp 的相机热点传图。关闭其他占用相机的软件；访客网络、AP 隔离、不同 VLAN 或 VPN 可能影响相机与手机的互通。支持正常 Wi‑Fi 客户端网络，目前未实现手机热点模式的专门适配。

自动发现使用 PCSS UDP 51562 广播、TCP 51560 回调；广播地址由手机实际 IPv4 前缀计算。手动 IP 先尝试旧协议端口 55740，失败后向指定相机执行发现。使用相机回调中公布的端口（实测 X‑T5 固件 4.31 为 15740），不把它固定为旧机型的 55740。握手使用实机验证通过的 libfuji 兼容字段，并重试 0x2019 相机忙响应；成功后使用富士的 PTP 数据流，继续执行完整保存和预览流程。

连接过的 Wi‑Fi 相机会在网络中断后最多尝试重连 3 次；发现或连接期间可点「断开」取消。不会自动切换手机 Wi‑Fi，也不会绑定整个应用进程的网络，只有相机套接字走选定 Wi‑Fi。

Wi‑Fi 通常慢于 USB，RAW 体积较大，先用 JPEG 验证。无线联机模式下存卡行为仍由相机设置决定。

## 无线下载速度优化（0.7.5 测试）

「⋮ → 设置 → 无线传输加速（测试）」默认开启，保存后在当前连接中立即生效。尝试在每批数据接收后提示 Linux TCP 及时发送 ACK，减少相机等待确认的时间；原图字节、文件校验、相册发布和 PTP 顺序事务保持不变。关闭时显式退出及时确认模式，系统不支持时自动回退。它只调整本应用的相机套接字，不改系统全局网络、路由器或其他应用。

此前真机低速样本中 99% 的接收耗时位于网络 read，私有文件写入只需几十毫秒；因此优先验证延迟 ACK，而不盲目扩大文件缓冲。`TCP_NODELAY` 控制本机发送的 Nagle 行为，不能替代接收方向的 ACK 设置；`TCP_QUICKACK` 是临时提示，需随接收重新应用。平板真实系统已通过 API 支持、开关与描述符生命周期检查；多组实拍已确认约 5–8% 的小幅差距，但尚不能用它解释此前所有约 300 KB/s 的低速。记录见 `docs/NETWORK_BENCHMARK.md`。

另有默认关闭的「Wi-Fi 活跃模式（测试）」：仅在 Wi-Fi 联机期间申请 Android 低延迟锁，切换设置立即申请/释放，断开、失败退出或服务销毁时释放。系统仅在屏幕亮起且 App 前台时实际启用此模式；官方文档指出它也可能降低吞吐，因此需要单独实测，不作为保证加速的默认设置。

## 原图下载时机

**⋮ → 设置 → 原图下载时机**，选择并保存：

- **停拍 3 秒后下载**（默认）：无线连拍先更新预览，停拍约 3 秒后开始原图保存；积压 8 项时提前保存。
- **立即下载**：完成优先预览后直接开始原图保存，省去主动等待的 3 秒。原图传输时新拍照片的预览可能等待当前事务完成。

保存后在当前连接生效并记住选择，无需断开重连；不打断正在传输的完整原图。手动「暂停原图」优先，切换模式不会自动恢复已暂停的下载，也不会清空队列。USB 继续直接接收；无线相机不开放预览能力时仍采用兼容的完整原图接收回退。

## 无线连拍与原图队列

- 最近照片栏与「图库」同时显示待保存队列，状态为待下载、下载中、正在保存或已保存；未完成原图以独立的预览条目显示，可以点开查看预览，完成前不能导出。图库打开时也会动态更新。
- 预览与保存事件带拍摄序号。跟随时显示最新预览，旧照片保存完成只加入图库，不把画面切回旧照片。「回到最新」会优先恢复最新待下载预览，重新打开界面时也可重放缓存的预览。
- 显示待保存数量 / 32、单张百分比、MB/s，以及完成后的排队、接收和最终保存耗时。接收速度为实际数据接收与私有落盘的有效平均速度，不等同于 Wi‑Fi 的连接速率。
- 支持分段读取的相机会先读取新照片的预览头，再以最多 256 KiB 分段补齐原图，在分段之间检查新照片。
- **本机 X‑T5 固件 4.31 无线模式实测拒绝 GetPartialObject（0x2005）**。因此当前使用兼容调度：先取独立缩略图，再按设置立即下载原图或停拍约 3 秒后下载；等待模式积压到 8 张时提前开始原图以释放相机缓冲区。最多跟踪 32 个对象。
- 这不等于无线通道能同时传送两张照片：一张完整原图传输开始后仍可能阻塞新预览。独立缩略图若不可用，自动回退完整原图顺序接收。0.6.1 真机两组各三张连续拍摄，独立预览获取为 41–209 ms，均先预览后补齐原图；该数值不是快门到显示的完整耗时，也不代表高速连拍帧率。
- 「暂停原图，优先拍摄」可暂时只取预览，点「开始保存原图」恢复。若一张完整原图已开始接收，暂停会在本张完成后生效；默认仍按用户选择自动保存。
- 32 是 App 追踪的文件数上限，RAW+JPEG 可能占两个条目；相机硬件缓存另有上限。达到 8 个排队对象时自动提前下载，达到 32 时界面提示保存以释放缓存。
- 原图在最终保存、长度校验及同步落盘后才释放相机对象；暂停或失败不释放未完成原图。状态显示“待保存”的照片仍未完成本地保存。

## 安装和拍摄

要求 Android 11 或以上，手机/平板支持 USB Host/OTG，使用支持数据传输的 USB‑C 线；必要时使用 OTG 转接器。手机必须作为 USB 主机。

1. 按下文构建并安装 `app/build/outputs/apk/debug/app-debug.apk`，或下载 GitHub Actions 生成的测试包。测试包使用开发签名；仅当签名一致时才能覆盖升级并保留应用数据。
2. X‑T5 → 网络/USB 设置 → 连接模式 → **USB 联机拍摄自动 / USB TETHER SHOOTING AUTO**。
3. USB 供电/通信设置选择 **自动** 或 **供电关/通信开**；将自动关机设为关闭。
4. 推荐先用 **JPEG FINE** 验证，再试 RAW+JPEG。连接手机，打开 App，点「连接 → USB 数据线连接」，允许 USB 访问。
5. 按下相机快门。应用自动轮询拍摄缓冲区，先尝试显示相机缩略图；JPEG 传输期间还会从文件头提取完整的 EXIF/FlashPix 预览，完成保存后显示清晰原图；RAF 显示相机内嵌 JPEG。
6. 「跟随」控制是否自动切换；点缩略图回看，双击或双指缩放。最近栏展示 30 个文件，「图库」以缩略图网格查看所有已接收文件。
7. 点「导出」把选中的 JPEG 复制到 `Pictures/XT5Tether`，RAF 复制到 `Download/XT5Tether`。

**存储说明：** App 图库的目录是 `Android/data/io.github.xt5tether/files/Pictures/Captures/`（外部应用目录不可用时回退到内部目录）。选择本地相册时原图保存到公共相册/下载目录。App 图库原图需先「导出」再卸载；公共相册原图不随卸载删除。联机模式下是否另存 SD 卡由相机设置决定，App 不改写存卡设置；请先用测试照片确认所需备份。

如提示状态不允许，退出相机菜单/回放，半按快门返回拍摄模式再连接。拔线后服务会停止；重新接线并点「连接相机」恢复。关闭 App 界面后，已经启动的联机服务可继续接收，通知中的「断开」可以停止。部分手机的电池管理可能影响后台运行。

## 已实现范围

- USB 授权、X‑T5 设备识别（`04cb:02fc`）、PTP 接口选择和断开处理。
- 打开联机会话，核验 X‑T5 型号及联机属性，保持相机优先，允许使用机身快门和拨盘。
- 每轮完成后间隔 200 ms 轮询富士拍摄临时存储区 `0x10000001`。这只是检测周期，**不是端到端出图时间**。
- 单线程顺序处理 USB 事务，分包/合包解码、事务编号校验、完整响应校验和 DeviceBusy 重试。
- JPEG/RAF 原文件以 16 KiB 分块接收、256 KiB 缓冲写盘，校验长度，`fsync` 后改名发布，再释放相机临时对象。
- 释放失败时保留已保存文件记录并重试，不重复下载；下一张复用同一对象句柄仍可接收。
- 缩略预览、EXIF 方向处理、历史照片、缩放、MediaStore 导出和诊断日志导出。
- 安卓前台服务类型为 `connectedDevice`，先检查 USB 授权再启动。

## 明确的限制

- 支持 USB 与同一路由器 Wi‑Fi 收图，不含蓝牙配对、远程快门、实时取景或参数控制。
- RAF 预览使用相机内嵌 JPEG，未实现 RAW 显影或 Capture One 色彩处理；RAF 原始字节完整保存。
- 照片先显示小预览，再按当前显示区域读取原文件；双击接近原像素比例，双指可继续放大。放大超过原像素比例不会产生额外细节。
- 可见细节单张位图预算为 40 MiB 与 Java 堆上限的 1/6 中较小值；尺寸过大或内存紧张时降低采样精度。RAF 细节仍受内嵌 JPEG 分辨率限制。
- 暂只接受 X‑T5 和已知的临时存储区。固件若暴露不同布局会停止并保留相机文件，需要实机日志适配。
- 未验证连拍吞吐、不同 USB 控制器、不同固件；不能承诺“零延迟”或固定帧率。
- 未完成的 `.part` 不会作为已保存原图展示；队列缩略图明确标示尚未保存，不会因预览成功而释放相机对象。相机断电可能丢失其易失缓冲区里的未接收照片。
- 手机进程恰好在本地保存后、相机释放前被终止，重连可能再次导入同一张，以保留照片为先。
- 缩略图调用依赖机身支持；不支持时直接接收原文件后显示。对于较大的 RAF，这一过程可能明显较慢。

## 构建和测试

使用 Android Studio 打开仓库根目录，或准备 JDK 17、Android SDK Platform 35、Build Tools 35.0.0。Gradle Wrapper 为 8.11.1，AGP 为 8.9.2。

配置 `ANDROID_HOME`，或在不提交的 `local.properties` 写入 `sdk.dir=你的Android SDK路径`。

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Windows PowerShell：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

输出：`app/build/outputs/apk/debug/app-debug.apk`。有 ADB 时可以 `adb install -r app/build/outputs/apk/debug/app-debug.apk`。

删除检查使用独立包 `io.github.xt5tether.checks`，复用生产代码但有独立 UID 和存储，不操作主应用实拍照片。只在真实设备运行：

```bash
./gradlew :device-checks:assembleDebug
adb install --no-streaming -r device-checks/build/outputs/apk/debug/device-checks-debug.apk
adb shell am instrument -w io.github.xt5tether.checks/io.github.xt5tether.PhotoDeletionDeviceCheck
adb uninstall io.github.xt5tether.checks
```

该检查只创建、删除命名为 DEVICECHECK 的临时照片，覆盖私有／相册／RAF 副本、删除边界、待保存排除、确认取消、新拍照片不误选、批量删除、空图库和 400 dp 窄窗口。测试执行状态见 `docs/VALIDATION.md`。如果设备拒绝测试包安装，应先在设备允许，不重复尝试。

拍摄参数提供只读真机检查工具，不安装测试包、不关闭主 App、不修改照片：

```bash
python3 tools/device/run_metadata_probe.py --serial DEVICE --photo /sdcard/Pictures/XT5Tether/EXISTING_PHOTO.jpg
```

工具需要与构建相同的 JAVA_HOME 和 ANDROID_HOME，临时程序与 APK 会在检查后清理；调用当前生产 PhotoSource 核对 EXIF 与实际图片尺寸。

另有真实设备布局回归工具：仅在相机已断开、无待保存照片时运行 `assembleDebugAndroidTest` 生成的独立测试 APK，再用 `adb shell am instrument -w io.github.xt5tether.test/io.github.xt5tether.LayoutStabilityInstrumentation` 启动。它会暂时占用界面并在结束时关闭测试进程；请勿与实拍交错执行，测试后重新打开主应用。覆盖平板布局、400 dp 窄窗口、全屏及 0/1/32 队列变化，不使用模拟器。

测试覆盖 USB 容器碎片与合并、事务错误、截断数据、错误响应、无数据阶段、无符号句柄、畸形元数据、文件长度、文件名路径过滤、同名照片保留、RAF 预览范围、相机控制优先级、只在成功保存后释放、释放忙重试、句柄复用、读卡器模式和存储区不匹配拒绝。

`docs/HARDWARE_TEST.md` 记录实机验收步骤，`docs/SOURCES.md` 列出官网及 GitHub 实现依据。GitHub Actions 工作流会执行相同构建检查并上传测试 APK。

## 项目结构

| 文件 | 作用 |
| --- | --- |
| `ptp/PtpClient.java` | 独立于安卓的 PTP/USB 协议、数据解析与流式下载 |
| `ptp/TetherEngine.java` | X‑T5 会话校验、轮询、接收与临时缓冲区释放 |
| `ptp/CaptureStore.java` | 完整保存、文件列表与 RAF 内嵌预览提取 |
| `UsbPtpIo.java` | Android UsbManager bulk 传输适配 |
| `ptp/FujiWifiIo.java` | 82 字节富士无线握手和 TCP PTP 数据流 |
| `ptp/FujiDiscovery.java` | PCSS 广播、相机回调解析和发现取消 |
| `ptp/FujiWifiConnection.java` / `WifiNetwork.java` | Wi‑Fi 套接字选择、指定 IP 与连接生命周期 |
| `TetherService.java` | 前台服务、串行接收任务、通知、状态与日志 |
| `MainActivity.java` | USB 授权、看图、历史、多选删除与导出界面 |
| `GallerySelection.java` | 按接收文件名维持多选，新照片不自动勾选 |
| `PhotoDecoder.java` / `PhotoView.java` | 文件与 MediaStore 预览、方向、缩放 |
| `PhotoLibrary.java` / `PhotoItem.java` | 保存位置设置、原图发布、两种来源的图库合并与归属校验删除 |

应用申请网络权限用于局域网相机通信，不申请定位或手机相机权限，不上传照片到云端。target SDK 保持 35，按 Android 官方兼容规则访问局域网；没有申请 target SDK 37 才要求的 `ACCESS_LOCAL_NETWORK`。Wi‑Fi 会话使用最长两小时的 CPU 唤醒锁，断开时释放。应用自身代码按 MIT 发布；参考项目和 AndroidX 许可见 `THIRD_PARTY_NOTICES.md`。
